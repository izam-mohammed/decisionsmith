## In short

decisionsmith is a Python library (published on PyPI as `decisionsmith`,
Apache-2.0) that starts a decision task (classify, route, screen, score,
yes/no) on an LLM teacher, logs every answer, fine-tunes a fast System One
student model (Laya, Jev) on those answers and moves traffic to it field by
field once the numbers say it is ready. It is used from Python
(`ds.harness`), from a CLI (`decisionsmith ...`), from an MCP server
(`decisionsmith mcp`) and from a Claude Code plugin (`plugin/`). Installed
with `uv add "decisionsmith[all]"` (`README.md`).

## What a person can use

### The harness

- One Pydantic schema drives the decision; `ds.harness(Schema, teacher=...,
  student="laya")` answers, validates and logs it, in four modes per field
  (`src/decisionsmith/core.py`, `src/decisionsmith/schema.py`; commit
  `5f759c5`).
- `h.status()`, `h.adapt()` and `h.finetune()` report readiness, calibrate
  thresholds and train the student, switching only when it is better
  (`src/decisionsmith/status.py`, `src/decisionsmith/training/`; commits
  `a1d3655`, PR `#7`).
- Engines: LLM providers, HTTP, Laya, structured output, System One
  (`src/decisionsmith/engines/`).

### Golden data, evaluation and saved models

- `ds.golden` picks texts worth labelling and writes a held-out split; a
  coding agent can label them through MCP with no LLM key
  (`src/decisionsmith/golden_set.py`, `src/decisionsmith/golden_session.py`;
  PRs `#3`, `#10`).
- Versioned model folders, `ds.load` and `model.evaluate` with a go/no-go
  report (`src/decisionsmith/artifact.py`, `src/decisionsmith/evaluation.py`;
  PRs `#1`, `#5`, `#6`).
- Resume state stored without pickle (`src/decisionsmith/training/checkpoint.py`;
  PR `#2`).

### CLI, MCP and the plugin

- `decisionsmith finetune | train | generate | golden | eval | bench |
  status | export | doctor | mcp`,
  every command with `--json` and fixed exit codes
  (`src/decisionsmith/cli.py`, `AGENTS.md`).
- An MCP server exposing the same tools (`src/decisionsmith/mcp.py`).
- A Claude Code plugin with commands, skills and subagents
  (`plugin/`, `.claude-plugin/marketplace.json`; PR `#10`).

### Integrations

- 21 framework integrations, each a lazily imported module with its own
  extra and pinned test group (`src/decisionsmith/integrations/`,
  `tests/integrations/pyproject.toml`, `docs/integrations.md`).

## Under the hood

- **Shape**: one package under `src/decisionsmith/`, built with `uv_build`
  (`pyproject.toml`); the core depends only on `pydantic` and `httpx`
  (`CONTRIBUTING.md`).
- **Data**: no service database; the harness log is a local SQLite file the
  user names (`src/decisionsmith/log.py`).
- **Integrations**: LLM providers and frameworks, each behind an optional
  extra (`pyproject.toml`, `docs/teachers.md`, `docs/integrations.md`).
- **Standards and CI**: Ruff lint and format, mypy, pytest with at least 95 %
  line and branch coverage per module (`scripts/check_coverage.py`) on Linux,
  macOS and Windows with Python 3.10 to 3.13 (`.github/workflows/ci.yml`);
  per-integration jobs (`.github/workflows/integrations.yml`); PR title
  check (`.github/workflows/pr-title.yml`); OpenSSF Scorecard
  (`.github/workflows/scorecard.yml`); CodeQL default setup (the "CodeQL"
  runs in `gh run list`); Dependabot for actions and uv
  (`.github/dependabot.yml`); pre-commit with uv-lock, Ruff, mypy and a
  commit message check (`.pre-commit-config.yaml`). Recorded in
  `docs/standards.md`.
- **Releases**: a `v*` tag runs `.github/workflows/release.yml`, which
  publishes to PyPI by trusted publishing and creates the GitHub release.
